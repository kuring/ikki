# 阶段 4：只读代码分析

## 阶段目标

让 Agent 在不修改代码的情况下完成代码理解任务，回答代码位置、调用链、错误原因和设计意图。

## 要学习的问题

- 什么是基于证据的代码回答？
- 为什么 Coding Agent 不能只靠模型记忆猜代码？
- 如何区分“我确认看到的事实”和“我的推断”？
- 证据不足时应该继续搜索还是说明不确定？
- 如何记录一次完整分析轨迹？

## 理论要点

- 只读分析是文件编辑前的安全练习。
- 好的代码回答应该能回到具体文件和代码片段。
- 推断可以有，但要和事实分开。

## 开发范围

- 代码问答模式。
- 证据引用要求。
- 搜索不足时的继续检索策略。
- 分析轨迹记录。

## 暂时不做什么

- 修改文件。
- 运行测试。
- 自动生成 patch。

## 实现任务

- [ ] 增加只读代码问答入口。
- [ ] 要求回答包含文件引用。
- [ ] 在证据不足时继续搜索。
- [ ] 在回答中区分事实和推断。
- [ ] 保存一次分析轨迹。

## 完成标准

- [ ] 能回答一个小仓库里的代码定位问题。
- [ ] 回答里能区分事实和推断。
- [ ] 回答包含具体文件路径。
- [ ] 打 tag：`v0.4-code-qa`。

## 复盘问题

- 哪些问题不适合只读分析直接回答？
- 证据引用到文件级、函数级还是行级更合适？
- 如何减少模型“看起来很懂”的猜测？
