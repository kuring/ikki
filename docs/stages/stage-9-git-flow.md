# 阶段 9：Git 工作流

## 阶段目标

让 Agent 能理解 diff、分支、提交和版本协作边界，成为更可靠的代码协作者。

## 要学习的问题

- Agent 为什么需要懂 git 状态？
- 如何区分用户已有改动和 Agent 新增改动？
- 什么时候应该创建分支？
- commit message 应该如何生成？
- Agent 能不能自动提交和推送？

## 理论要点

- Git 是代码协作的安全网。
- 修改前后都要理解工作区状态。
- 自动提交和推送需要更明确的用户意图。

## 开发范围

- git status 读取。
- diff 展示和摘要。
- 分支信息读取。
- commit message 辅助生成。
- tag 辅助。

## 暂时不做什么

- 默认自动提交。
- 默认自动推送。
- 强制 reset 或覆盖用户分支。

## 实现任务

- [ ] 读取当前分支。
- [ ] 读取工作区状态。
- [ ] 区分已存在改动和本次改动。
- [ ] 生成 diff 摘要。
- [ ] 生成提交说明草稿。
- [ ] 在危险 git 操作前要求确认。

## 完成标准

- [ ] Agent 能解释当前 git 状态。
- [ ] Agent 能展示本次修改 diff。
- [ ] Agent 不会误覆盖用户改动。
- [ ] 打 tag：`v0.9-git-flow`。

## 复盘问题

- 哪些 git 命令属于危险操作？
- Agent 应该何时建议提交？
- 如何处理未跟踪文件？
