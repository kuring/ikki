# 阶段 5：安全命令执行

## 阶段目标

让 Agent 能运行低风险命令，并在危险操作前停下来确认。

## 要学习的问题

- Shell 工具为什么是高风险工具？
- 什么是命令白名单、黑名单和确认点？
- dry-run 在 Agent 中有什么价值？
- 如何限制命令的工作目录、超时时间和输出大小？
- 哪些命令必须要求用户确认？

## 理论要点

- 命令执行是 Agent 能力跃迁点，也是风险跃迁点。
- 安全边界应该在工具层实现，而不是只靠 prompt。
- 命令输出需要截断和摘要，否则会污染上下文。

## 开发范围

- `run_command` 工具。
- 工作目录限制。
- 超时控制。
- 输出截断。
- 危险命令识别。
- 用户确认点。

## 暂时不做什么

- 自动执行破坏性命令。
- 远程生产环境操作。
- 提权命令。

## 实现任务

- [ ] 实现只允许工作区内运行命令。
- [ ] 设置命令超时。
- [ ] 限制输出大小。
- [ ] 定义危险命令规则。
- [ ] 对高风险命令要求确认。
- [ ] 记录命令、退出码和输出摘要。

## 完成标准

- [ ] Agent 能运行安全检查命令。
- [ ] 危险命令不会被直接执行。
- [ ] 命令失败时能把错误返回给模型。
- [ ] 打 tag：`v0.5-safe-shell`。

## 复盘问题

- 白名单和黑名单哪个更适合早期实现？
- 哪些命令属于“看似普通但风险很高”？
- Agent 如何避免无限重试失败命令？
