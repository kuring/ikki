# 阶段 6：文件编辑能力

## 阶段目标

让 Agent 能用最小 patch 修改文件，并保护用户已有改动。

## 要学习的问题

- 为什么文件编辑要尽量小？
- 如何在修改前确认文件当前内容？
- 如何避免覆盖用户未提交改动？
- patch、整文件重写和结构化编辑各有什么风险？
- 修改后应该如何展示 diff？

## 理论要点

- 文件编辑必须建立在证据和当前文件状态之上。
- 保护用户改动比“快速改完”更重要。
- diff 是用户审查 Agent 行为的主要界面。

## 开发范围

- 文件读取校验。
- patch 修改。
- diff 展示。
- 用户改动保护。
- 编辑失败恢复。

## 暂时不做什么

- 大规模重构。
- 自动格式化整个仓库。
- 跨文件复杂迁移。

## 实现任务

- [ ] 设计文件编辑工具接口。
- [ ] 修改前读取目标片段。
- [ ] 应用最小 patch。
- [ ] 修改后展示 diff。
- [ ] 检测文件是否在过程中被改动。
- [ ] 失败时给出恢复建议。

## 完成标准

- [ ] Agent 能修改一个小文件。
- [ ] 修改前后 diff 清晰可见。
- [ ] 不会覆盖用户已有改动。
- [ ] 打 tag：`v0.6-edit`。

## 复盘问题

- 什么时候应该拒绝编辑？
- 多文件修改时如何组织计划？
- 如何让用户快速看懂改动？
