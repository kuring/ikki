# 阶段 1：最小对话 Agent

## 阶段目标

在阶段 0 已经能调用真实模型的基础上，做一个真正有 Agent 雏形的最小对话循环。

## 要学习的问题

- Agent loop 是什么？
- system prompt、user message、assistant message 分别承担什么职责？
- 单轮调用和多轮对话有什么区别？
- 上下文窗口为什么会影响 Agent 表现？
- 会话历史应该保存在哪里，保存到什么粒度？
- 调试时应该如何看到发送给模型的真实消息结构？

## 理论要点

- Chatbot 只需要回答一次，Agent 需要在任务、状态和环境反馈之间循环。
- system prompt 是行为边界，不应该塞太多临时任务细节。
- 会话历史不是越多越好，需要考虑上下文窗口和成本。

## 开发范围

- 默认 system prompt。
- 标准消息结构。
- 单轮问答。
- 简单多轮会话历史。
- 调试模式下展示发送给模型的消息。

## 暂时不做什么

- Tool Calling。
- 文件读取和代码仓库搜索。
- 长期记忆。
- 自动压缩上下文。

## 实现任务

- [ ] 设计默认 system prompt。
- [ ] 定义 message 数据结构。
- [ ] 支持一次完整问答。
- [ ] 支持在同一会话中继续提问。
- [ ] 增加调试输出或日志，展示模型输入消息。

## 完成标准

- [ ] 可以执行一次完整问答。
- [ ] 可以继续一段简单多轮对话。
- [ ] 可以看到发送给模型的消息结构。
- [ ] 打 tag：`v0.1-chat-loop`。

- system prompt 应该写多细？
- 哪些历史消息应该进入下一轮上下文？
- 什么时候应该截断或总结历史？
