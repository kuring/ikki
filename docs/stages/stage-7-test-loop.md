# 阶段 7：测试修复循环

## 阶段目标

让 Agent 能运行测试、读取失败信息，并根据失败继续定位和修复。

## 要学习的问题

- Observe-Think-Act 循环在代码修复中是什么样？
- 测试失败输出应该如何摘要？
- Agent 什么时候应该继续修，什么时候应该停下来？
- 如何避免同一个错误反复尝试？
- 如何记录每次修复尝试？

## 理论要点

- 测试是代码 Agent 最重要的外部反馈之一。
- 失败输出需要结构化提取，而不是全部塞进上下文。
- 重试需要上限和理由。

## 开发范围

- 测试命令配置。
- 测试执行工具。
- 失败输出解析。
- 修复循环。
- 重试上限和停止条件。

## 暂时不做什么

- 自动生成大型测试套件。
- 并行测试调度。
- CI 集成。

## 实现任务

- [ ] 支持配置测试命令。
- [ ] 运行测试并收集退出码。
- [ ] 提取失败摘要。
- [ ] 根据失败继续搜索和编辑。
- [ ] 设置最大修复轮数。
- [ ] 保存每轮尝试记录。

## 完成标准

- [ ] Agent 能运行测试并理解失败。
- [ ] Agent 能根据失败完成一次修复。
- [ ] 达到重试上限时会停下说明原因。
- [ ] 打 tag：`v0.7-test-loop`。

## 复盘问题

- 哪些失败适合自动修复？
- 如何判断修复是否引入新问题？
- 测试输出太长时如何压缩？
