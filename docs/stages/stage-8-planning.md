# 阶段 8：任务计划系统

## 阶段目标

引入计划、步骤状态和长任务控制，让 Agent 不再只靠一次模型输出推进复杂任务。

## 要学习的问题

- Planning 对 Agent 有什么价值？
- 什么时候需要显式计划，什么时候直接执行更好？
- 步骤状态应该有哪些？
- 失败重试和改计划的边界在哪里？
- 如何让用户看懂 Agent 当前进度？

## 理论要点

- 计划不是装饰，它应该约束执行和恢复。
- 长任务需要可观测状态。
- 计划可以修改，但修改本身也应该被记录。

## 开发范围

- todo/plan 数据结构。
- 步骤状态管理。
- 计划展示。
- 失败重试策略。
- 用户确认点。

## 暂时不做什么

- 多 Agent 调度。
- 复杂项目管理系统。
- 自动跨会话恢复。

## 实现任务

- [ ] 定义计划和步骤结构。
- [ ] 增加步骤状态：待执行、进行中、完成、阻塞。
- [ ] 在长任务中展示计划。
- [ ] 支持根据观察更新计划。
- [ ] 记录计划变更原因。

## 完成标准

- [ ] Agent 能为复杂任务生成简短计划。
- [ ] 执行过程中能更新步骤状态。
- [ ] 失败时能说明阻塞点或下一步。
- [ ] 打 tag：`v0.8-planning`。

## 复盘问题

- 计划应该多细？
- 什么时候应该让用户确认计划？
- 计划变化是否会降低用户信任？
